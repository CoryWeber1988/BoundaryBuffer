What the tool does

Field Boundary Buffer reads an existing field boundary and creates a new polygon that is physically larger or smaller than the original. Recorded boundaries often leave too little room inside for different machines, because equipment has physical dimensions outside its working area (turning, headlands, trailing implements, obstacles). The adjusted boundary lets you plan for that clearance.

Boundaries can have exterior polygons (the field edge) and interior polygons (holes such as wetlands, buildings or rock piles). The tool handles both together. The original and adjusted outlines are shown on the map at the same time, and the adjusted result can be exported in several formats with the original attributes preserved.

Everything runs in your browser. Your files are not uploaded anywhere. An internet connection is needed to load the map tiles and the supporting libraries.

Quick start

  1. Read the disclaimer on the landing page and choose I accept.
  2. Load a boundary file (step 1). The map zooms to it.
  3. Check the polygon list (step 3). Fix any polygon whose exterior/interior type is wrong.
  4. Enter a buffer size (step 4). Use a negative number to shrink the field, positive to grow it. Leave the projection on the recommended UTM zone.
  5. Click Apply buffer. The adjusted boundary appears in orange over the original in blue. Check it against the imagery.
  6. Name the file and choose a format (step 5), then click Export adjusted boundary.

1. Loading a boundary

FormatHow to load
ShapefileSelect a .zip containing the shapefile, or select the .shp, .dbf and .prj together (the .shx can be included but is not needed). Only polygon shapefiles are read.
KMLSelect the .kml file. Polygon outer and inner boundaries are read.
KMZSelect the .kmz file. The KML inside is read.

You can also drag and drop files onto the map. Each ring in the file becomes one polygon in the list, and each keeps the attributes of the feature it came from (shapefile columns, or KML name, description and extended data).

If a shapefile has no attribute table, the output simply contains the buffer column. If you select several shapefiles at once, they are combined, and the first projection found is used for all.

Loading a new file replaces the current boundary and the applied buffer. Your buffer size, units, projections and export settings are kept (see Resets).

Projection of the source file

  • Automatic: if a .prj is present, it is read and the status line under the file box shows what was detected. KML and KMZ are always WGS 84.
  • No .prj: if the coordinates look like longitude/latitude, WGS 84 is assumed and the status line says so. Otherwise the tool asks you to assign a projection and shows nothing until you do.
  • Manual: type an EPSG code or a proj4 string in the box and click Assign. This works at any time, including to override a wrong automatic detection. Built-in EPSG codes: 4326, 3857, WGS 84 UTM (32601-32660, 32701-32760), NAD83 UTM (26901-26923) and NAD83(CSRS) UTM zones 11-18 (2955-2962). For anything else, paste a proj4 string such as +proj=utm +zone=17 +datum=NAD83 +units=m +no_defs.

If the coordinates do not fit the chosen projection (for example they land outside valid latitudes), the tool tells you and you can assign another.

2. Units

Choose Imperial (acres, feet and inches) or Metric (hectares, metres and centimetres). The default is imperial. The same choice is on the landing page and in the sidebar, and they stay in sync. Changing it updates every area immediately. The buffer size you typed is converted so it keeps the same physical distance (ft becomes m and in becomes cm, and the reverse).

3. Polygons and area

The list

Each polygon shows its number, area and a drop-down to set it as Exterior or Interior. Click a row to zoom to that polygon. Exterior polygons are drawn with solid lines and interior polygons with dashed lines.

Automatic exterior and interior

  • A polygon with nothing around it is exterior.
  • A polygon inside another polygon is interior.
  • A polygon inside an interior polygon (an island inside a hole) is exterior again, and so on, alternating with each level.

Use the drop-down to override any polygon. An interior polygon belongs to the smallest exterior polygon that contains it. An interior polygon with no exterior polygon around it cannot be used and is marked no parent, ignored.

Totals

LineMeaning
Exterior totalSum of exterior polygon areas.
Interior total (subtracted)Sum of interior polygon areas that belong to an exterior polygon.
Net area (original)Exterior total minus interior total. This is the number to use as the field area.
Net area (adjusted)Same calculation on the buffered result, shown after you apply a buffer.
ChangeAdjusted minus original, with the percent change.

Areas are calculated on a spherical earth model from the WGS 84 coordinates. They can differ slightly (a small fraction of a percent) from ellipsoidal values in desktop GIS software.

Changing a polygon's type clears any applied buffer, because the result no longer matches. Apply the buffer again.

4. Buffer

Size and direction

Enter a number and pick a unit. Units follow the tool's unit system: feet or inches for imperial, metres or centimetres for metric. The value is applied to the field as a whole:

EntryExterior boundaryInterior polygons
Positive (for example 10)Moves outward (field gets bigger)Shrink
Negative (for example -10)Moves inward (field gets smaller)Grow

A negative buffer is usually the choice for equipment clearance: the working area pulls in from the edge and keeps farther away from obstacles. Corners that are rounded off by a growing buffer stay sharp on a shrinking one. Very narrow parts of a polygon can disappear when shrinking, and an interior polygon can merge with the boundary or with another one. If the buffer removes the whole boundary, the tool tells you and keeps the previous result.

Buffer projection

The polygons are re-projected to a flat, metre-based projection before buffering and then converted back. The default is the recommended UTM zone for the middle of your boundary, which keeps distances accurate to well under 0.1%. The list also offers:

  • NAD83 UTM zone for the same area when you work in North America.
  • Web Mercator (EPSG:3857), which stretches distances away from the equator. At Ontario latitudes that is around 35%, so a 10 ft buffer would measure about 7 ft on the ground. A warning with the figure for your location is shown when it is selected, with a button to switch back to the recommended UTM zone.
  • Custom EPSG for any code from the built-in list in the projection section above.

For a boundary that spans two UTM zones the recommended zone is the one containing its centre. Very large areas are better served by a custom projection.

Apply and clear

Apply buffer creates the adjusted boundary in orange over the original in blue and updates the adjusted area and change. Changing the size and applying again replaces the previous result. Clear removes the adjusted boundary and keeps your settings.

5. Export

File name

Type a name without the extension. With Append buffer size to file name checked, the buffer is added to the name, for example north_field_buf-10ft or north_field_buf+3m. The box is filled with the name of the loaded file.

Formats

FormatOutputNotes
Shapefile (default).zip with .shp .shx .dbf .prj .cpgFollows the output projection. Text is UTF-8. A .prj is written for the built-in EPSG codes only. Column names are limited to 10 characters, so long names are shortened and made unique.
KML.kmlAlways WGS 84. Attributes are written as extended data.
KMZ.kmzThe same KML, zipped.
GeoJSON.geojsonFollows the output projection. A coordinate system entry is added when it is not WGS 84.
ISOXML.zip containing TASKDATA/TASKDATA.XMLAlways WGS 84. One field per output polygon with a boundary (exterior ring plus interior rings) and its area. This is a minimal boundary-only file. Test it in your display or software before relying on it.

Output projection

The default is WGS 84 (EPSG:4326). You can switch to Web Mercator, the recommended UTM zone, NAD83 UTM or a custom EPSG code from the built-in list. It applies to shapefile and GeoJSON; the other formats always use WGS 84.

Attributes and the buffer column

Every attribute column from the original file is carried to the output. An added column named Buffer_ft, Buffer_in, Buffer_cm or Buffer_m (matching the unit you are using) holds the signed adjustment, positive for growth and negative for shrinkage. Each output feature takes the attributes of the exterior polygon it was made from. Attributes of interior polygons are not carried. If shrinking splits a polygon into several parts, each part becomes its own feature with the same attributes.

The buffer value written is the one last applied, shown in the unit currently selected. If you change the buffer entry after applying, apply again before exporting.

The map

Use the layer button on the map to choose a background and turn overlays on and off.

  • Backgrounds: Esri World Imagery (default), Esri Streets, Esri Topographic, OpenStreetMap, OpenTopoMap and USGS Imagery (United States coverage only).
  • Overlays: Original boundary, Adjusted boundary and Place labels.

Hover over or tap a polygon to see its number, type and area. Imagery resolution and date vary by location. Check how current the imagery is before judging a boundary against it. Background tiles come from third-party servers and are subject to their terms of use.

Processing several boundaries with the same settings: set the buffer, projections and export options once, apply and export, then simply load the next file. Your settings stay in place. Click Apply buffer again for each new boundary, since the result is specific to a file. The file name updates to match each new file.

Sidebar, mobile and themes

  • Panel button hides or shows the sidebar. The sidebar scrolls, and each step can be collapsed. On a phone it opens over the map and starts hidden after a file loads so the map is visible.
  • Dark / Light switches the theme. The choice is remembered by your browser.
  • The tool works on desktop and mobile browsers. On a phone, use the Panel button to move between the map and the settings.

Limits and accuracy

  • Only polygons are read. Lines, points and multi-layer files are not supported.
  • Buffering uses rounded corners and straight offsets. It does not know about the shape of any machine, so check the result against your equipment and obstacles.
  • Invalid polygons (for example edges that cross themselves) are repaired before buffering, which can change their shape slightly.
  • The result is only as good as the source boundary. Original GPS error, gaps and spikes remain.
  • Reading is done in the browser. Very large files with many thousands of vertices or polygons can be slow.
  • Source files with elevation or measure values are read in 2D only. Those values are not written to the output.

Troubleshooting

ProblemWhat to try
Map is grey or the tool says libraries are missingCheck your internet connection. The map and libraries load from the internet.
"No polygons found"Select the .shp with its .dbf/.prj together, or use a .zip. Confirm it is a polygon file.
Boundary appears in the wrong place or not at allThe projection was not detected correctly. Assign the right EPSG code or proj4 string in step 1.
A hole is not subtracted from the areaIt is marked as exterior, or it has no exterior polygon around it. Set it to Interior in the list.
The buffer looks smaller than enteredCheck the buffer projection. Web Mercator shrinks real-world distances at northern latitudes. Use the recommended UTM zone.
The imported file does not open elsewhereFor shapefiles, unzip first if the software does not read zips. For ISOXML, confirm which folder layout your display expects.
No .prj in the exported shapefileThe output EPSG code is not one of the built-in codes. Choose a built-in output projection.
